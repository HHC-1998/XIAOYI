# 04_语音输入与识别详解

> 语音链路（章节号 `04 §`）：浏览器采集 → 转 WAV → ASR 转写 → chat → TTS 合成。
> 相关文档：[05_前端详解](05_前端详解.md)（语音按钮/VoiceRecorder）· [06_一键启动详解](06_一键启动详解.md)（Dockerfile whisper 预下载）· [08_桌面助手详解](08_桌面助手详解.md)（实时语音对话）· [11_2D虚拟人物详解](11_2D虚拟人物详解.md)（TTS 口型同步）

## 1. 语音链路总览

```mermaid
flowchart LR
    A[浏览器采集<br/>Web Speech API 或 MediaRecorder] --> B[解码 16kHz 单声道 WAV<br/>frontend utils/audio.js blobToWav16k]
    B --> C[POST /api/voice/transcribe]
    C --> D[convert_to_wav<br/>已 16k mono 直接透传 / ffmpeg 兜底]
    D --> E[ASR 转写<br/>本地 faster-whisper / OpenAI]
    E --> F[memory_engine.chat]
    F --> G[TTS 合成<br/>edge-tts 在线（晓晓）]
    G --> H[audio.playbackRate = 1.25 播放]
```

## 2. 采集路径（前端）

- **主路径**：浏览器原生 **Web Speech API**（`webkitSpeechRecognition`，`continuous + interimResults=true`），说话时实时回调整串写入输入框。**注意**：Web Speech 是浏览器云端识别（非本地），属云端例外——国内网络下必失败，故有失败记忆自动降级本地模式。
- **降级路径**：Firefox / Safari 不支持或 Web Speech 失败时，降级为 MediaRecorder + 后端 `/api/voice/transcribe`（VAD 分段「边录边出字」）。
- **Web Speech 失败记忆**：`rec.onerror` 的 `network/service-not-allowed/audio-capture` 置 `webSpeechFailedRef=true`，仅首次提示「已自动切换本地识别模式」；后续点击直达本地识别（国内网络 Chrome 下 Web Speech 必失败）。
- 录音中点击麦克风外任意处 / 切换路由自动 `stop()`；录音中点击发送 = 一次完成「关麦 + 发送」（`stopAndGetText` + `markTextSent`）。

## 3. 转 WAV（关键，勿回退 webm 直传）

MediaRecorder 产出的 webm blob **必须先经 `frontend/src/utils/audio.js` 的 `blobToWav16k()`** 解码为 16kHz 单声道 WAV 再上传——ffmpeg 7.x 解析 Chrome MediaRecorder 非 seekable webm 报 `AVERROR_EOF`(187)、转写全线 500。后端对 16kHz 单声道 WAV 直接透传（`_is_16k_mono_pcm_wav()` 探测命中即返回原路径），其余格式走 ffmpeg 兜底（`timeout=60`）。同文件 `float32ToWavBlob()` 供桌面助手 Silero VAD 用（onSpeechEnd 直接给 16k Float32Array，无需解码，见 08 §3/§4）。

## 4. ASR 封装（`backend/app/core/asr_provider.py`，04 §8）

- 统一走 `/api/voice/transcribe`；未配置 OpenAI Key 时自动用本地 **faster-whisper small**。
- **占位符视为未配置**：`_PLACEHOLDER_KEYS` 过滤 `your-key-here` 等，占位符 / 空串一律走本地模型（否则调 OpenAI 云转写报 401）。
- **转写参数（勿删）**：

```python
# LocalWhisperASR
model.transcribe(
    audio_path, language="zh", beam_size=5,
    vad_filter=True, vad_parameters=dict(min_silence_duration_ms=500),
    initial_prompt="小亦，XIAOYI，你好，请问。",   # 专名热词
    condition_on_previous_text=False,
)
# OpenAIWhisperASR
transcriptions.create(..., language="zh", prompt="小亦，XIAOYI，你好，请问。这是一段中文口语对话。")
```

- 容器内必须构建时预下载 whisper 模型（`backend/Dockerfile` 的 `WhisperModel('small', ...)`，走 Clash 代理），否则运行时下载失败转写恒空。
- 转写失败返回 422 中文提示（「音频转写失败，请重试或稍后再试」），不裸 500。

## 5. TTS 封装（`backend/app/core/tts_provider.py`，04 §9）

- **edge-tts 在线合成（2026-09-03 十八轮，替换 piper）**：调用微软 Edge 免费在线神经语音，中文音色默认 `zh-CN-XiaoyiNeural`（晓伊，2026-09-03 用户试听选定，元气活泼更贴人设），语调/停顿自然。`Communicate(text, voice, rate, pitch).save(mp3)` 直出 mp3（无需 wav 中转 + ffmpeg 转码）。
- **为何替换 piper（2026-08-28 引入）**：piper 本地合成虽完全离线，但 `huayan-medium` 是约 60MB 小模型，prosody 能力弱、断句差，机械朗读感强；用户 2026-09-03 确认接受 TTS 联网换取自然度（见台账十八轮）。
- **env 可配**（`backend/app/config.py`）：`XIAOYI_TTS_VOICE`（默认 `zh-CN-XiaoyiNeural` 晓伊，可回晓晓 `zh-CN-XiaoxiaoNeural` / 云希 `zh-CN-YunxiNeural` 等）、`XIAOYI_TTS_RATE`（语速，默认 `+10%`，用户试听选定更俏皮）、`XIAOYI_TTS_PITCH`（音调，默认 `+0Hz`）。
- **云端例外声明**：TTS 是 AGENTS.md「不接任何云端 API」的**唯一有意例外**（用户 2026-09-03 确认）；聊天 / 抽取 / 向量仍全本地 Ollama。联网不可用时 `/api/voice/tts` 返回 422，服务不崩溃。
- `/api/voice/tts`：清洗 Markdown 符号 + 过滤 emoji（前后端双保险），**省略号（`……`/`...`/`。。。`）→ 空格**（edge-tts 遇省略号会明显停顿，朗读层去除、文字显示保留，2026-09-03）；>5000 字符返回 422「文本过长」，合成失败返回 422「语音合成失败，请稍后重试」。
- 播放 `audio.playbackRate = 1.25`。

## 6. 语音接口（`backend/app/api/voice.py`，04 §7）

| 接口 | 说明 |
|---|---|
| `POST /api/voice/transcribe` | 上传 WAV 转文字；>10MB 返回 422（预检上限与音频一致，常量 `MAX_FILE_SIZE`） |
| `POST /api/voice/tts` | 文字合成语音，返回音频文件（`audio/mpeg`，`BackgroundTask` 响应后清理临时文件） |

两个接口均需携带 JWT（`Authorization: Bearer <token>`），未登录返回 401；鉴权失效不影响前端本地识别降级路径。

`transcribe` 处理链路：大小预检（>10MB 422）→ 写临时文件 → `convert_to_wav`（16k mono 透传 / ffmpeg 兜底）→ `asr.transcribe` → 返回 `{text}`；`finally` 清理临时与 `*_16k.wav`。

> 注意区分两个体积常量：语音接口预检用 `MAX_FILE_SIZE`（10MB，上传音频上限）；数据导入用 `MAX_IMPORT_SIZE`（50MB，09 §5）。两者用途不同，勿混用。

## 7. 共享音频工具（`backend/app/core/audio_utils.py`，04 §8.2）

- `convert_to_wav(src, dst=None)`：把任意音频格式转 16kHz 单声道 wav（faster-whisper 需要）。输入已是前端解码的 16kHz 单声道 16-bit PCM WAV 时直接返回原路径（不调 ffmpeg，绕开 webm 问题）；其余格式输出独立 `*_16k.wav`。
- `_is_16k_mono_pcm_wav(path)`：解析 WAV 头 `fmt ` 块探测采样率/声道/位深，命中即透传。
- 依赖系统级 ffmpeg（06 后端 Dockerfile 已安装；Windows 需加入 PATH）。

## 8. 桌面助手语音

桌面助手页打开即自动监听、离开自动停止，实时语音对话（VAD 监听 / 打断 / 句级 TTS），详见 `08_桌面助手详解.md`。

**VAD 引擎（2026-09-03 起）**：桌面助手实时监听已从振幅阈值替换为 **Silero VAD（@ricky0123/vad-web v5，浏览器本地 ONNX 推理）**——判断"是不是人声"而非"音量够不够大"，嘈杂环境（汽车/空调/旁人说话）不误触发、不死锁。模型/worklet/wasm 由 `npm postinstall`（`frontend/scripts/copy-vad-assets.mjs`）拷入 `public/vad2/` 本地加载，无外网依赖；参数与打断语义见 08 §3，资产布局与拷贝脚本见该节。

### 8.1 流式 ASR（sherpa-onnx，"边听边出字"，2026-09-03，台账 38 节）

**背景**：faster-whisper 是整段式引擎，只能"说完再转写"——半句会认错、后字会改口，做不了边说边出字（用户诉求：说话时逐字上屏、停嘴即得整句，消除"正在识别"干等）。引入流式引擎 sherpa-onnx（本地 CPU，只追加不回跳）为桌面助手识别主路，whisper 降级为兜底。

- **引擎与模型**：`sherpa-onnx`（pip，自带 ONNX Runtime）；模型选 `sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23`（zipformer transducer，70.6MB，中文流式最成熟）。目录 `backend/models/sherpa-asr/`（文件：`encoder-*.onnx`/`decoder-*.onnx`/`joiner-*.onnx`/`tokens.txt`）。**不进 Docker 镜像**（`.dockerignore` 排除 models/），由 compose bind mount `../backend/models:/app/models` 挂入；可用 `XIAOYI_STREAM_ASR_DIR` env 覆盖路径。
  - **模型族（2026-09-04 收紧，台账 39 节）**：**只支持 zipformer transducer 三件套**（`encoder-*.onnx`/`decoder-*.onnx`/`joiner-*.onnx`/`tokens.txt`）——zh-14M / bilingual-zh-en（487MB）/ multi-zh-hans-int8（59MB）全是 transducer 带 joiner，换同族模型只须换文件不改码。**绝不按"有无 joiner/文件名"自动猜测 paraformer**：sherpa-onnx C++ 层在模型与加载器不匹配时 LOG(FATAL) 直接 abort、Python 无法捕获，曾致 backend 整个进程猝死（exit 255，见台账 39 节）——文件不全一律 Python 层报错、由 WS 端点降级 whisper，后端永不崩。
- **后端**：`backend/app/core/stream_asr.py` —— 单例 `OnlineRecognizer` 懒加载（首次 WS 用到才建，`num_threads=2`，加载失败缓存异常重抛）；`available()` 检查目录（tokens + 三件套**齐全**才算可用）；`new_stream/feed/finish` 异步封装（`asyncio.to_thread` + 单把线程锁，识别器非线程安全，多路 WS 串行化）；`finish` 补 0.4s 尾静音 + `input_finished` 冲刷出尾字。模型缺失/不完整/加载失败抛 `RuntimeError` → 调用方降级。
- **WS 端点** `GET /api/voice/asr-stream?token=<JWT>`（`backend/app/api/voice.py`）：鉴权失败 `close(4401)`；模型缺失先发 `{"type":"error"}` 再 `close(4403)`（前端回退 whisper）；否则 `ready`。协议：二进制帧 = 16k mono Float32 PCM；文本帧 = `speech_start`（建流，旧流未清先 reset）/`speech_end`（收尾取 final）/`cancel`（丢弃，VAD misfire 用）；返回 `partial`（结果变化才发）/`final`/`error`。同一 WS 消息串行处理（消息 await 期间不 receive 下一条），天然无并发竞态。
- **前端**：`frontend/src/api/voice.js` `openStreamAsr()` 封装 WS（`location.protocol` 拼 ws(s)、token query、Float32Array→ArrayBuffer）；`DesktopAssistant.jsx` 状态机要点见 08 §4。partial 仅展示不提交（字回跳防污染已合并文本）；final 经 `fixAsrNames`（小艺/小依/小E/XIAOYI…→小亦，提交层归一，流式无热词）+ 触发词检查后走 `commitUserText`。**流式路径合并窗口并行（2026-09-04，台账 41 节）**：`onSpeechEnd` 流式分支在 `end()` 前先行 `scheduleMergeWindow()`——窗口从"停嘴"起算、与后端 final 收尾并行（旧实现 final 回来才由 `commitUserText` 兜底补挂 = 白等 final+~1s）；final 在窗口内到达，`commitUserText` 有"无窗才补挂"守卫不重置窗口，总延迟收敛 1s（自停嘴），与 whisper 兜底路径对齐。
- **兜底与回退**：WS error/close、模型未下载 → `streamAsrOkRef=false` → `onSpeechEnd` 自动走 faster-whisper 一次性转写（原链路原样保留，网页聊天页 VoiceRecorder 语音不受影响始终 whisper）。zipformer-zh-14M 实测识别率不佳时换 `bilingual-zh-en`（487MB）或 `multi-zh-hans-int8`（59MB），glob 探测自动适配。

**端到端延迟账单（2026-09-03 压缩后，目标"说完话 → 回复首句"≤2s；流式 ASR 8.1 为主路径后，本账单描述 whisper 兜底链路的延迟模型）**：VAD 判句结束 `VAD_REDEMPTION_MS=400ms` → **合并窗口与 ASR 转写并行**（2026-09-03 首响提速，台账 37 节：窗口从"停嘴"起算、与 faster-whisper 转写并行，旧实现窗口在转写完成后才挂 = 停嘴后白等 ~2s；并行后转写 ≤1s 时提交请求 ≈ 停嘴 + 1s）+ ASR 本地 faster-whisper（beam_size=1）≈0.5~1s（并行不另计）+ 记忆检索 + LLM 首 token + **TTS 完整句立即入队**（2026-09-03 首响提速：普通完整句不再攒满 18 字，首句到标点即合成，小亦口癖短句首声提前 0.5~1.5s）。后端收尾提速：回复向量改后台异步写（`_persist_reply` SQL 同步落库、Chroma 后台写，不再拖住 SSE `[DONE]`）、embedding 超时 30s 定稿（60s→10s→30s：10s 在冷启动 xiaoyi 加载抢队列时让 bge-m3 超时丢向量，放宽到 30s 后台写容忍慢）——修复"第二句卡在思考中"（卡死根因见台账 32 节）。**Ollama 模型驻留**（台账 33→36 节：永久驻留决策，2026-09-03 定稿）：宿主机 `OLLAMA_KEEP_ALIVE=-1`（永久驻留，41 节更正：实为 4G 显存，chat+bge 同驻 ~3G 可容）+ `OLLAMA_MAX_LOADED_MODELS=3`（extract=qwen3:0.6b 小模型三驻不互踢，41 节由 4b 降回）；代码侧 `_model_configs` 的 chat/embedding `keep_alive` 写 `-1`——注意 embedding 走 Ollama 原生 `/api/embed` 其 keep_alive **真实生效**（请求级会盖过宿主机，故必须 -1，否则 bge-m3 停聊 30m 仍被卸）；chat 走 `/v1` 不识别 keep_alive（以宿主为准，-1 仅表意）。效果：**开机/Ollama 启动后加载一次，除重启外永不冷启动**；单次 embed ~100ms。**KG 抽取让路**（台账 34/35 节）：qwen3:4b 图谱抽取延迟到停聊 ≥60s 的间隙执行（`_MEMORY_IDLE_SECONDS`，35 节由 15s 调高——正常停顿不再触发 qwen 中途加载占 Ollama），extract/vision `keep_alive=30s` 用完即走不占驻留位，连续对话期间不打扰。

## 9. TTS 引擎说明（2026-09-03 十八轮起 edge-tts）

**无需下载任何模型**。edge-tts 走微软 Edge 在线服务，容器/后端进程能出网即可用（`python start.py` 重建后端镜像安装依赖后生效）。

```powershell
# 换音色（可选）：改 .env 的 XIAOYI_TTS_VOICE 后重启，默认晓晓 zh-CN-XiaoxiaoNeural
# 常用中文音色：晓晓 zh-CN-XiaoxiaoNeural（女，默认）/ 晓伊 zh-CN-XiaoyiNeural（女，活泼）
#               云希 zh-CN-YunxiNeural（男）/ 云扬 zh-CN-YunyangNeural（男，新闻）
# 语速/音调：XIAOYI_TTS_RATE=+10%  /  XIAOYI_TTS_PITCH=+5Hz（改 .env 后重启）
```

- **历史（piper，2026-08-28 ~ 09-03）**：本地合成 `zh_CN-huayan-medium.onnx`（约 63MB，手动下载至 `backend/models/piper/`，代码上溯三级 parent 定位 / piper-tts 1.7.0 AudioChunk API 适配见台账十六、十七轮）。因机械朗读感强，2026-09-03 换回 edge-tts，`backend/models/piper/` 目录与 `piper-tts` 依赖已删除。
- 网络不可用时 TTS 返回 422 并提示「语音合成失败」，聊天/ASR 等其他功能不受影响（前端有文字兜底，不卡对话）。
