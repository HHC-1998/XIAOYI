# 13_配套硬件详解（吧唧 · 硬件端小亦）

> 本文件记录小亦的**硬件形态设想**——一枚带屏幕、带摄像头、能独立联网的圆形"吧唧"徽章（别在胸前 / 磁吸贴手机背）。它承接 `12_视觉功能详解` 预设的"挂在胸前的小吧唧"硬件形态，把散落在各文档的硬件相关假设集中成一份**立项前讨论稿**。当前仅"设想 + 需求讨论"，未进入任何采购 / 开发。
> 章节号 `13 §`。

## 1. 需求动机

小亦的软件（聊天 / 记忆 / 桌面助手 / 视觉）已成型，但她的"身体"还在网页与桌面助手页里。用户希望她**走进现实**：一枚可别在身上的圆形小徽章（吧唧），正面是一张小亦的脸（屏幕），能看见世界（摄像头）、能听见你（麦克风）、能开口说话（扬声器）。

- **聊天**：想聊时看着她的脸说话，像现在桌面助手页那样，但捧在手里 / 别在胸前。
- **陪伴展示**：不想聊时别在身上，屏幕朝外亮着小亦的脸，像一枚"活着的徽章"。
- **视觉**：摄像头朝前拍眼前风景（对应 12 §3 每 2 分钟轮询拍照的"拾光/每日精彩"），与网页视觉功能同一套后端。
- 本质：**现在的"桌面助手"网页 = 这台吧唧的模拟器**。吧唧只是给小亦换一个"身体"，真正的灵魂（后端 / 记忆 / 模型）原样复用。

## 2. 硬件形态

### 2.1 使用场景与两个姿势

| 姿势 | 行为 | 屏幕朝向 | 摄像头 |
|---|---|---|---|
| **磁吸贴手机背** | 出门 / 收纳，NFC 一吸唤起 APP | 朝外（也可翻面） | 朝外拍风景 |
| **别在胸前 / 包上** | 独立佩戴，只当聊天助手 | 朝外 | 朝外拍风景 |

- 屏幕与摄像头**同面朝前**（"脸"与"眼睛"一体的吧唧正面）。
- 平时只听声音（麦克风收音），不主动出声；**想聊才拿起来对着说**。
- 贴手机背时"一吸即连"：手机 NFC 触发 → 自动打开 APP → 蓝牙握手 → 接管配置/登录。

### 2.3 关键尺寸与选型（未定，待调研）

- 尺寸对齐**标准吧唧 58mm**（也可 44mm / 75mm）。屏选 **2.1 寸圆屏**（直径约 53mm）+ 边框 ≈ 58mm；小一号可选 1.28 寸 240×240 圆屏（智能手表级）。
- 圆屏方案：常见 GC9A01（240×240，SPI）等。

## 3. 账号与"一吸即连"

- **账号在手机 APP 上登录**；吧唧本身不承载账号体系。
- **绑定逻辑**：吧唧第一次配对 = "这台吧唧认领给你"。吧唧只认你，你的知识库 / 图谱天然就是它的。
- **"一吸"技术**：手机背面 NFC 线圈 + 吧唧内 NFC 标签 → 触发自动打开 APP → 蓝牙(BLE)传输配对 → APP 下发 WiFi / 服务器配置。
- 当前为**个人一对一产品**（后端单机部署），多用户 / 多吧唧 / 多租户是产品化后期话题，不阻塞原型。

## 4. 联网方式（WiFi vs 4G vs 蓝牙）

| 方案 | 说明 | 流量费 | 适合阶段 |
|---|---|---|---|
| **蓝牙连手机** | 贴手机背时，走手机网络；功耗低 | 无 | 第一版原型最省事 |
| **WiFi 独立** | 吧唧自己连家中 WiFi 访问后端 | 无 | 原型调试（在家） |
| **实体 SIM 卡槽** | 用户自己插卡（Nano-SIM / 流量卡），流量自理 | 用户自理 | 产品化中期（卡槽占空间、需开盖） |
| **4G / eSIM 内置** | 设备内写 eSIM；流量多由厂商包在售价 / 订阅里，或对接运营商让用户自助开通 | 厂商或用户 | 走量产品（展会竞品主流） |

> **当前结论**：原型阶段优先 **WiFi**（甚至蓝牙），别为 4G/eSIM 卡住；"让用户自己塞卡"对应实体卡槽，是产品化后期选项。详见当日讨论记录（9-3 台账）。

## 5. 成本与阶段划分

| 阶段 | 内容 | 成本量级 | 说明 |
|---|---|---|---|
| **原型机** | 现成开发板（如 ESP32-S3 + 圆屏一体板）+ 麦克风/喇叭/电池 | 约百元（板）~ 几千（外包固件） | 验证形态与体验；固件找懂 ESP32/Arduino 的兼职外包 |
| **工程样机** | 定制 PCB / 结构件 / 磁吸 / 防水 | 数万级 | 需硬件工程师；仅产品化后 |
| **量产** | 开模 + 认证 + 供应链 | 数十万级起 | 暂不考虑 |

> 吧唧**不做任何本地推理**（跑不动也无需跑）。主控只负责：屏显 / 录音推流 / 播放 / 轮询拍照上传。所有智能都在现有后端。

## 6. 软件对接展望（不阻塞原型）

- 现有 `POST /api/voice/transcribe`（ASR）、`/api/voice/tts`（edge-tts 在线合成）已可被任意客户端调用——吧唧只需"录音 → 上传转写 → 文本走聊天 → 播放返回的语音"。
- 表情 / 嘴型：吧唧屏幕显示小亦的脸（Q 版图 / 简易 Live2D 输出），说话时可按 TTS 音频驱动嘴型（对照 11 文档口型同步思路）。
- 摄像头 / 轮询：对接 12 文档的 `POST /api/vision/photo` 等视觉链路。

## 7. 隐私与安全要点

- 摄像头朝前 + 自动轮询拍风景 → **会拍到他人**。处理方向（2026-09-03 讨论定调）为 **AI 抹除留景**：人像检测 → 生成遮罩 → LaMa 类图像修复模型用背景补画"抹掉"人，只保留干净风景（Apache 2.0 可商用，模型 ~200MB，CPU 即可跑、无需实时）。相比"打码/模糊"，抹除后**人彻底消失、零可识别性**，隐私最干净，且为"小亦入镜"功能铺路（见 §8）。局限：人被独特物体挡住 / 大特写时背景补画会露馅，产品上可对低置信结果做兜底（不入库或标注 AI 处理）。
- 收音：常听待机需唤醒词或显式开关，避免一直收音的隐私与耗电问题。
- 贴胸佩戴的摄像头设备在社会场景有"偷拍感"风险，需明显指示灯 / 形态克制。

## 8. 未来功能展望（远期彩蛋，不阻塞当前）

> 2026-09-03 讨论：抹人留景的真正产品价值不止"隐私"，而是**给小亦清出舞台**。

- **小亦入镜打卡**：把抹除后的干净风景当背景，将小亦虚拟形象（Live2D / Q 版图）合成进照片 → "小亦替我打卡了这片晚霞 / 街角"。同一套"干净背景"资产将来可复用：用户上传真人照 → 与小亦合成"合照"。合成难点（光影 / 比例 / Live2D 动作）为后话，等现有功能调通、能带出门实测后再立项。
- **卡通化路人**（AnimeGANv2 等，MIT 移植版）曾为备选，因"整图动漫化违背保留原景"且"局部卡通化接缝易假"被否；将来或作为趣味滤镜彩蛋单做，不与隐私安全绑定。
